# Color profiles

Ready-made `*.prf` profiles in the editor's own format. To use them:

1. Copy the files you want into the `Profiles` folder that sits next to `settings.ini`
   and `op_doc.ini` (create it if it does not exist).
2. Open **Settings > Color Profiles...**, press **Add Rule**, type the extension, choose the
   profile and press **Save**.

| Profile | Suggested extensions |
|---|---|
| `C` | c |
| `Cpp` | cpp, cc, cxx, hpp, hxx |
| `H` | h |
| `Python` | py, pyw |
| `JSON` | json |
| `PHP` | php |
| `Java` | java |
| `PicASM` | asm, inc |
| `Rust` | rs |
| `Go` | go |
| `Pascal` | pas, pp, dpr, lpr |
| `CSS` | css |
| `HTML` | html, htm |
| `Txt` | txt |

The programming-language profiles use the Solarized accent colors, which read well on both
the Day and the Night theme: green for control flow, yellow for types, blue for storage
classes and modifiers, magenta for literals, orange for preprocessor and imports, cyan for
library calls, violet for special forms. They are generated by `tools/gen_color_profiles.py`;
edit the lists there and run `python3 tools/gen_color_profiles.py` to regenerate them.
`Txt.prf` is hand-written and is not touched by the script.

Phrase rules are plain case-insensitive substring matches without word boundaries, so keywords
are written with a trailing space or bracket (`if `, `printf(`) to limit false matches inside
longer words. Some false matches remain (for example `int ` inside `print `).
